The Challenge

Datakimia is a multi-tenant white-label analytics SaaS (US): each customer is isolated in its own deployment. The challenge: deliver embedded BI and conversational AI data agents securely per customer, and keep the BI layer (Apache Superset fork with ~430 custom commits) up to date without breaking production.

What I Built

NestJS Backend (37 Endpoints)

Founded and authored the production backend (first commit May 2024): Google/Microsoft Entra/Auth0 login, JWT tokens, role-based access control derived from Superset permissions, CASL-based authorization, per-customer data isolation. Production-grade for 2+ years without customer-facing downtime.

Superset Embedding & RBAC

Guest token generation for embedded dashboards with row-level security filters applied per customer. Dynamic dashboard filtering by customer context. Secure iframe embedding in the Next.js frontend.

Conversational AI Data Agents

Built chat-based data exploration over BigQuery using Google Gemini Data Analytics API (streaming SSE responses). Implemented voice agent with Gemini Live API for spoken data queries. Users ask questions in natural language; the agent translates to BigQuery SQL and returns insights.

Apache Superset 4.1 → 6.1 Migration

Migrated Datakimia's heavily customized Superset fork across 3 major versions (Sep 8 – Oct 7, 2024, ~30 calendar days). Process:

  • Inventory of ~430 custom commits classified into carry/replace/drop
  • 6 upstream merges with AI-assisted conflict resolution (Cursor) inside deterministic checks
  • Final merge touched ~4,400 files
  • 23 automated wiring checks; caught 3 features that had silently broken
  • 5-phase, 17-step smoke test (local → ephemeral → pilot → preprod → prod)
  • Effort: ~100 hours over 30 days

Stack

Next.js 14 (frontend), NestJS 10 (backend), Prisma ORM, PostgreSQL, Apache Superset, BigQuery, Google Gemini, GKE, Helm.
